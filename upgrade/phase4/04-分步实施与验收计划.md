# P4.1–P4.4 分步实施与验收计划

这是 P4.0 的后续施工建议，不是开工记录。以 [P4.0 任务](https://app.notion.com/p/41a5421e690b813b8004c9495eed1027) 和 [2.0 正典](https://app.notion.com/p/4135421e690b815eb404c3024c860134) 的 2026-11-16 裁定为准。P4.0 经用户审阅后，再决定建立或启动 P4.1；本轮不创建后续执行任务。

## 1. 依赖和交付节奏

```mermaid
flowchart LR
    A[用户审阅 P4.0 方案与原型] --> B[P4.1 独立资源启动]
    B --> C[P4.2 认证 / HTTP / WS / IPC / 核心功能]
    C --> D[P4.3 三栏 UI / IndexedDB / 草稿 / 离线]
    D --> E[P4.4 GNOME Wayland 真机 / 视觉审阅 / DEB 候选]
    E --> F[用户接受阶段交付]
```

每步只在仓库 `main` 小步提交：检查用户改动 → fetch/核对 `origin/main`（仅 fast-forward）→ 对应范围检查 → review staged diff → Conventional Commit → 正常 push → 核对本地与远端 SHA → 回写任务。独立可验证步骤各自提交，不把工程完成等同用户接受。阶段 Task 交付后仍为 **In progress**。若 main 分歧、检查失败或疑似敏感内容，停止发布该步并报告；不建 worktree 绕过。

P4.1/2 可用最小功能画面验证工程闭环；P4.3 才完成整套视觉与本地体验。每个阶段保留已通过场景、失败样例和未验证项，不重复运行与改动无关的大规模测试。

## 2. P4.1：独立资源启动

前置：P4.0 用户接受；独立执行任务已获授权。仅做 Desktop 自有启动路径、资源与开发 Profile，不触碰 Gateway。

| 小步 | 交付 | 验收出口 / 证据 |
| --- | --- | --- |
| 1.1 目录和资源 | `apps/desktop` 自有 renderer、Vite/pnpm 构建入口、品牌资源、预置新 tokens；包不依赖 `apps/web/dist` 或 Bridge 页面 | 干净环境可重复构建；本地资源清单完整；源与打包后的 Oracle Eye 摘要一致；无旧主题导入 |
| 1.2 本地壳 | 建议 `oraculum-app://bundle/` 固定本地资源协议、sandbox/contextIsolation、封闭导航、最小 preload；独立正式/开发 Profile | 路径穿越、编码穿越、符号链接逃逸、未知资源拒绝；renderer 无 Node、任意 IPC、远程脚本；不调用 `ensureBridge`、systemctl 或启动 Gateway |
| 1.3 脱网启动 | 启动页/连接入口/基本外观恢复、最小三栏骨架；不实现正式业务页面 | 使用未配置 endpoint 的独立 Profile 启动，仍显示本地 UI；只在 Desktop 测试进程拒绝联网，验证缺失 Gateway 提示，不停止真实 Gateway |

必要检查：Desktop TypeScript/构建、资源 containment 与 CSP、窗口导航/sender 负向检查、基础 Ubuntu Electron 运行。开发日志不得含凭据或私有 endpoint。旧 `runtime.cjs` 的服务启动行为仅作反例；不能将服务名替换为 Gateway 后继续沿用。[旧启动调用](../../apps/desktop/main.cjs#L119)、[旧服务探测/启动](../../apps/desktop/runtime.cjs#L13)

回退：回退本步骤尚未发布的 Desktop 源码/候选二进制；不删除 Profile、草稿或 journal。旧 Desktop 文件保留为历史参考，不重新启用旧 Bridge。

## 3. P4.2：Gateway 通信、安全与核心能力

前置：独立资源壳通过。先 fixture 完成 main transport/有限 IPC，再对已有 Beta 3 做本机 HTTP/WS 验证。不是另建一套 Gateway。

| 小步 | 交付 | 验收出口 / 证据 |
| --- | --- | --- |
| 2.1 endpoint / 配对 / 凭据 | main 中 URL 规范化、协议 major/能力协商、配对与短 access 更新；安全存储与原生错误映射 | HTTP 仅 loopback；HTTPS/WSS 配置入口可保留；Origin + Base Path 的 `/` 和非根路径可在 fixture 验证；凭据不在 renderer/URL/日志；安全存储不可用时拒绝明文降级 |
| 2.2 读取 / 事件 | Schema 验证、项目/会话分页、Snapshot/Item details、WS heartbeat/replay/reset 与刷新合并 | 重复、乱序、缺口、epoch/installation 变化、未知 state event、活动流与快照重叠均不生成重复正文；失去同步时不解锁写入 |
| 2.3 写入 / 审批 | main journal 先持久 operationId，再发送；receipt 查询；发送、停止、插话、会话管理与审批 | 覆盖发送前崩溃、请求到达 ACK 丢失、accepted 后 UI 崩溃、Gateway 代次变化的 fixture；unknown 仅查询，无自动重发、无清除屏障按钮；accepted 不冒充 Turn 完成 |
| 2.4 文件 / Inspector 能力 | 主机目录与项目注册、文件 grant/内容、附件、Diff/Plan/子代理/扩展/用量；原生选择/保存/通知适配 | IPC 不接受任意主机路径/URL/RPC；下载核对摘要；附件上传与后续 Turn 的两个 operationId 正确关联；缺失能力显示真实受限原因 |
| 2.5 真实本地闭环 | 专用 Desktop 身份与专门测试项目，通过现有 Beta 3 完成配对、读取、发送/流式/停止与恢复 | 标注“真实本机 HTTP/WS + 官方 Codex”；只操作测试范围，不修改现有项目/会话；记录脱敏 receipt/最终状态、协议/能力及客户端来源 SHA |

完整 UI 功能清单和路由以 [复用与 API 映射](02-源码复用与API映射.md) 为验收表。每类能力必须有可用、不可用、权限/同步不足的交互；不能只验证最短聊天路径。真实原生审批是否能稳定触发依官方运行时，无法触发则保留 fixture 证据并报告真实场景缺口，不能虚构通过。

安全验证在客户端进程内做：伪 sender/子 frame、超限载荷、任意 IPC channel、路径/URL 注入、撤销/令牌过期、协议 major 不兼容、模型/权限覆盖与最近原生回读分离。main 根据最新授权/能力及同步事实判断；renderer 按钮状态不是权限依据。[协议验证/事件分类](../../packages/gateway-protocol/src/index.ts#L14)、[权限读取事实](../../gateway/src/permission-readback.ts#L1)

回退：关闭 Desktop 测试进程，保留其 journal 与专用 Profile。对已送达或未知的操作只查询收敛，不重放、不以回退恢复旧回执状态；不回退 Gateway。

## 4. P4.3：三栏 UI、本地数据与离线

前置：P4.2 main transport/安全与核心路由可用。实现 P4.0 用户接受的视觉基线；不搬旧页面 CSS，不接入旧主题设置。

| 小步 | 交付 | 验收出口 / 证据 |
| --- | --- | --- |
| 3.1 视觉与组件 | Navigation / Conversation / Inspector、Composer、菜单/对话框；Light/Dark/OLED Dark | 同一关键场景三主题对照；OLED 基础背景 `#000000`；文字/状态/焦点可读；无满屏卡片；品牌与原型差异有说明 |
| 3.2 本地分层 | Zustand 内存投影；IndexedDB history/drafts/preferences 分库；main 独立 journal；每个连接/身份命名空间隔离 | 清 history 不清草稿/journal；数据库损坏、配额不足、升级被旧窗口阻塞时能提示/恢复；持久化失败阻止发送并保留编辑内容；跨库无伪原子保证 |
| 3.3 历史与阅读 | 分页窗口、historyRevision 校正、item details 摘要、阅读锚点、会话草稿 | 长历史打开/返回保持已加载页；revision 改变旧游标作废；晚到响应不覆盖新会话；用户向上阅读时流式不抢滚动；大条目按需展开 |
| 3.4 离线与恢复 | 缓存只读、离线草稿、连接状态、unknown 集中呈现与对账入口 | 离线新建/发送/审批/项目写操作禁用；重连先确认身份/事件/快照/回执再开放相应写操作；无自动发送草稿；撤销身份后不能把旧缓存当在线授权 |
| 3.5 键鼠和系统体验 | 面板开关、搜索、上下文菜单、快捷键、IME、缩放、文件与通知定位 | 键盘完成核心路径；中文候选确认 Enter 不发送；危险写入不能由单键误触；焦点离开 Inspector 可回到来源；退出窗口后无后台客户端/Tray承诺 |

本地历史只存可重建投影；缓存命中和 freshness 从不证明执行权限。按已观察的真实瓶颈确定缓存容量与性能目标；先记录机器、数据集、构建类型、冷/热打开、长历史滚动/内存、流式延迟、数据库大小与恢复耗时，不承诺未经测量的毫秒指标。参考 [Android 只读同步策略](../../apps/android/app/src/main/java/dev/oraculum/poc/repository/SyncReadPolicy.kt#L10) 的语义，不共享 Kotlin UI 或照搬固定时限。

基本外观恢复只重置新版主题/缩放/布局，不删除凭据、草稿、历史以外的安全记录。关闭窗口退出；正常退出等待草稿落盘，但退出不取消远端 Codex Turn。主进程异常退出后下次启动凭 journal 查询恢复，不能自动补发。

## 5. P4.4：真实 Ubuntu 体验、审阅和 DEB 候选

前置：P4.3 功能与数据层通过。按当前 Ubuntu GNOME/Wayland 主机建立可重复验收；不要以浏览器原型、mock 或 Xvfb 代替正式 Electron/OS 证据。

| 小步 | 交付 | 验收出口 / 证据 |
| --- | --- | --- |
| 4.1 真实桌面 | GNOME/Wayland 上独立应用，系统选择器/保存/打开/通知、IME/快捷键/缩放/窗口退出 | 记录 OS/桌面/Electron 版本及真实 sandbox；无 `--no-sandbox`；原生控件与取消路径实际可用；通知点击定位正确、去重、关闭后不承诺送达 |
| 4.2 真实 HTTP/WS | 已有 Beta 3 + 专用测试项目的核心路径和断线恢复 | 仅断 Desktop transport/挂起测试进程，不停止或重启 Gateway；恢复无重复 Turn/审批；Gateway 进程启动标识与重启计数前后相同；结果不足则保留限制 |
| 4.3 视觉审阅包 | 三主题关键页、普通/窄窗口、Inspector/审批/离线/连接页截图，标明真实运行与 fixture | 截图可直接审阅，附索引和场景；用户评价视觉/信息密度/交互，工程检查不能替代视觉接受 |
| 4.4 独立包候选 | 独立 `oraculum-desktop` DEB、可执行入口/desktop entry/图标、来源SHA/版本/摘要/许可证 | 只构建候选，不发行/安装本机；静态包清单及获准的一次性安装环境验证：不含 Gateway、systemd、凭据、旧数据/主题、开发路径；不占 Gateway 的 `oraculum` CLI |

包应自行携带 renderer、preload、main 与品牌/字体许可资源。构建脚本和验证器须适配新版身份，不能直接以旧 `oraculum` DEB 验证器得出通过结论。[现有旧打包范围](../../scripts/build-desktop.mjs#L18)、[旧验证器身份断言](../../scripts/verify-deb.mjs#L31)

回退：保留候选与证据，修复 Desktop 后重新验证受影响项；不将候选安装、发布、服务重启或网络变更混入视觉审阅。正式发布/安装另行授权。

## 6. 保护现有 Gateway 的具体工作法

1. 所有 UI 与异常场景默认使用纯 fixture 或客户端 transport stub，不执行仓库 `gateway`、`gateway:cli init`、`test:gateway:live`、`test:gateway:faults` 或旧 Desktop 启动命令。这些命令可能启动实例或执行真实操作，不适合直接套用本机服务。
2. P4.0 不读取运行配置、配对文件、数据库、进程环境，不向服务发送请求。只读 systemd 的 ActiveState/SubState、MainPID、启动标识、NRestarts 可用于前后保护核对，不在公共仓库记录私有配置和实例参数。
3. 后续真实验证只从用户提供的配置入口取得本机 endpoint；公开源码只保留可移植参数。单独创建 Desktop 客户端 Profile/设备身份，配对走现有正规接口；保留已有设备信任，不共用 Android token。
4. 真实写测试须使用专门测试目录和会话，并先列出作用范围。不得为了制造重启、撤销或网络异常而修改生产配置/服务或用户现有项目。重启/epoch 等故障用 fixture；不把 fixture 结果称为真实服务重启通过。
5. 遇到协议/API 缺口：记录客户端操作、当前Schema/源码/能力依据、最小复现（去敏 fixture 优先）、用户影响与建议 → 停用该控件或显示受限 → 独立讨论 Gateway 改动 → 获单独授权后才在另定的隔离验证中处理。不要偷偷开测试 Gateway 或回退 Bridge。
6. 测试设备身份、测试目录/会话和回执的清理另列准确范围；不自动删除可能仍有关联的 unknown、原生会话或其他设备数据。

## 7. 证据等级和验收清单

| 等级 | 能证明 | 不能证明 |
| --- | --- | --- |
| P4.0 静态源码/原型 | 路由映射、设计可读性、fixture交互、主题核心对比度、交付文件自洽 | Electron 安全运行、真实配对/写入、IndexedDB可靠性、GNOME系统行为 |
| 客户端单测/fixture | 负向校验、事件合并、存储/崩溃算法、协议兼容分支 | 正式 Codex 能力或系统集成已可用 |
| 真实本机 HTTP/WS | 指定主机、已有 Beta 3、专用身份/项目的实际链路 | HTTPS/WSS、公网/TLS/证书、别的主机、真实服务重启恢复 |
| 真实 Electron/GNOME | 指定构建的 sandbox、窗口/输入/文件/通知和实际视觉 | 正式发行/安装成功、全部桌面环境兼容 |
| DEB 静态/一次性环境 | 候选包完整性、身份/依赖、该环境安装行为 | 本机已经安装或用户已接受 |

最终逐项核对：核心能力映射无遗漏；三主题与基本恢复；HTTP loopback/HTTPS入口和Base Path；main凭据/有限IPC/文件边界；unknown先对账；缓存可失效、草稿与journal保全；离线只读/不自动发送；GNOME/Wayland实证；独立包身份；Gateway保护记录；Git本远端一致；Notion链接/状态回读；所有未验证项如实列出。HTTPS/WSS实链路是保留的未来验证项，不阻塞本阶段已批准的本机联调范围。
