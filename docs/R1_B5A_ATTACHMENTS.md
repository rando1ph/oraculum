# R1-B5-A attachment input

This implements input only. B5-B preview/download/share needs separate acceptance
and authorization. No endpoint in this batch reads arbitrary host files.

## HTTP and ownership contract

- `POST <entry-base>attachments`: `application/octet-stream`, raw request stream.
  `X-Oraculum-Upload: 1` and an exact `Origin` are required in addition to the
  existing HttpOnly, SameSite device cookie. `X-Oraculum-File` is percent-encoded
  JSON `{cwd, threadId, draftId, name, mime, size}` (at most 8192 header characters).
  The thread must already be tracked/resumed in the registered canonical project.
- Response: `{id, name, size, mime, kind, expiresAt}`. IDs and draft IDs are UUIDv4;
  IDs are generated by the Bridge. Original filenames are display metadata only.
- `POST <entry-base>attachments/remove`: ordinary small JSON
  `{cwd, threadId, draftId, id}`, same authentication/Origin/CSRF header. Only the
  uploading device's ready attachment can be removed.
- `turn/start` accepts `attachmentIds` plus `draftId` and the normal text/settings.
  Paths, file content, `content://`, and native input arrays are not accepted from
  the renderer. IDs must belong to this device, project, thread and draft, be
  complete/unexpired, unique, and pass inode, link, size and SHA-256 checks.
- Images become actual native `localImage` inputs. Documents become JSON-quoted
  paths in a generated text suffix; the official Codex tools retain all existing
  sandbox/approval behavior. No Office extraction or extra directory permission.
- Snapshot `attachments` and `attachmentsChanged` carry `AttachmentDelivery`
  metadata scoped to native turn IDs. Expired/missing files have `available=false`;
  historical cards are not upload capabilities. No download/thumbnail HTTP API.

## Filesystem and retention

`<registered-cwd>/.oraculum-attachments/<server-uuid>/input.<validated-extension>`
is the only binary storage location. Directories use 0700; files finish at 0400.
The inbox contains a self-ignoring `.gitignore` (`*\n`), including itself. This
prevents normal Git discovery, not deliberate `git add -f`. Existing nonempty
foreign inboxes are rejected, never adopted. No user research directory is used
for tests.

Linux descriptor-relative IO opens each ancestor without following symlinks and
compares the pinned project inode with the existing project registry before the
first write. The inbox, upload directory and file identities are pinned; final
paths and content are revalidated before native submission. Cleanup only unlinks
the generated filename inside a pinned owned directory, never recursive paths.
An administrator or malicious process running as the same Unix user can still
change files after validation; this is not a separate host-user security boundary.

Small metadata tables in the existing private Bridge SQLite store record project
and inbox identities, attachment ownership, digests, lifecycle and delivery IDs.
They hold no binary, document body, prompts or device credentials. Attachment
claims and send receipt reservation commit in the same transaction. A crash or
ambiguous native result leaves `held` material pinned indefinitely; there is no
automatic resend, deletion or unknown-result resolution. Explicit native rejection
releases the IDs to ready state; native acceptance binds them to the real turn.

Ready uploads expire after 24 hours; confirmed sent files after 30 days. Cleanup
runs once per minute and before uploads. Unknown (`held`) uploads never expire.
Missing/replaced directories fail closed and may leave orphaned files for future
explicit maintenance; no broad filesystem scan/delete is attempted.

Limits: 6 files / draft, 20 MiB / file, 50 MiB / batch, 2 concurrent streams globally,
1 / device, 24 attempts / device / minute and 60 globally, 256 retained files /
1 GiB globally, 200 MiB / device. Reserve at least 256 MiB of disk plus one maximum
file before each stream. Transfer deadline 120 seconds, idle deadline 15 seconds,
minimum mean rate 1 KiB/s after 15 seconds. Authentication is checked every chunk
and every 250 ms while idle. Streaming uses backpressure and bounded sniff/hash
buffers. All ordinary JSON and WebSocket limits remain 64 KiB.

## Verification commands

- `pnpm check`, `pnpm test`, `pnpm build`
- `pnpm exec tsx scripts/attachments-native.ts`: isolated temporary Codex HOME,
  project and offline loopback provider; actual native `localImage` protocol and
  workspace sandbox file-read probe, no real model inference or credentials.
- `pnpm exec vitest run bridge/src/attachments.test.ts`: device/Origin/path,
  streaming/type/retention/receipt and filesystem safety cases.

Native probe on the installed CLI 0.164.0 accepts the inputs without any CLI
upgrade. The temporary-HOME helper-alias warning is harmless and recorded; this
does not establish model comprehension or final Android Release behavior.
